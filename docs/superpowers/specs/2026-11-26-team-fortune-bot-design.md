# 쓱부엉 Teams 운세 봇 설계

작성일: 2026-11-26 · 버전: 1.0 · 대상: 프로젝트 소유자와 구현 담당자

## 1. 목적과 합의 범위

쓱부엉은 평일 아침 9시에 팀 단체 대화방에 12띠 운세 카드 한 장을 올리는 Teams 봇입니다.
예전 신문 한쪽에 실리던 띠별 운세처럼 팀원이 함께 보고 웃는 재미가 목적입니다.
운세는 오락용이며 정답 데이터가 없습니다. 등급(별점)은 전통 띠 관계 규칙으로 정하고, 문장은 LLM이 캐릭터 말투로 씁니다.

2026-11-26 대화에서 사용자가 확정한 내용은 아래와 같습니다.

- 콜네임 `쓱부엉`. 쪽지를 쓱 두고 가는 내성적인 부엉이입니다.
- GitHub 저장소 `teams-fortune-bot`. 세계관 이름은 이 작업에서 다루지 않습니다.
- 공개 방식은 단체방 전체 공개 띠별 카드입니다. 출생연도는 표시하지 않고 띠만 표시합니다.
- 카드 형태는 「한 줄형 + 펼쳐보기」입니다(시안 `mockup/index.html`).
- 추가 요소 4가지: 머리글 요약 한 줄, 요일과 특별한 날 문구, 쓱부엉 근황 한 줄, 생일 쪽지.
- 생일은 모두 양력입니다.
- 문장 생성은 발송 직전 LLM 1회 호출 방식(아래 3절의 방식 A)입니다.
- LLM은 Gemini를 쓰되, 문장 품질을 위해 장부장보다 상위 모델인 Gemini 3.6 Flash를 씁니다.

이번 단계의 산출물은 이 설계 문서입니다. 문서 승인 후 별도 구현 계획을 작성합니다.

## 2. 참조 구조와 파일 구성

참조 저장소는 `../team-meal-bot`(냠요정)입니다. 정해진 시각에 단체방으로 먼저 메시지를 보내는 구조가 같기 때문입니다.
TypeScript, Express, Microsoft Agents SDK(`@microsoft/agents-hosting`), Node 내장 `node:sqlite`, Docker Compose를 그대로 씁니다.
LLM은 `../teambi-agent`(장부장)와 같은 Gemini API를 쓰고 환경 변수 이름(`GEMINI_API_KEY`, `GEMINI_MODEL`, `GEMINI_REASONING_EFFORT`)을 맞춥니다. 모델은 문장 품질을 위해 장부장과 다르게 정합니다.

| 경로 | 책임 |
| --- | --- |
| `src/index.ts` | 서버, JWT 인증, Teams 수신, 멘션 명령, 30초 주기 예약 실행. 냠요정 `index.ts` 구조를 따릅니다 |
| `src/domain.ts` | 일진 계산, 띠 관계와 등급, 세부 운세, 행운 메뉴·색, 머리글 요약, 생일 대상 계산. 외부 호출이 없는 순수 함수만 둡니다 |
| `src/llm.ts` | Gemini 호출, 응답 검증, 실패 시 템플릿 문장 |
| `src/cards.ts` | 운세 카드, 도움말 문구 |
| `src/store.ts` | SQLite 스키마, 대화방 참조, 날짜별 운세, 발송 기록 |
| `src/scheduler.ts` | 발송 시각 판정. 냠요정 `scheduler.ts`의 한국 시간 계산 방식을 씁니다 |
| `src/holidays.ts` | 냠요정 파일을 그대로 복사합니다 |
| `test/*.test.ts` | 파일별 테스트 |
| `appPackage/` | `manifest.json`, `color.png`, `outline.png` |
| `scripts/package-teams-app.sh` | 쿠웨이트박 스크립트 기준. 앱 ID 치환과 Teams 설치 ZIP 생성 |
| `deploy/team-fortune-bot.service` | 기존과 같은 Compose 실행용 systemd 서비스 |
| `.github/workflows/security.yml` | 기존 네 봇과 같은 보안 검사 |
| 루트 설정 | `package.json`, 잠금 파일, TypeScript 설정, Dockerfile, `compose.yaml`, `.env.example`, `.gitignore`, README |

런타임 의존성은 냠요정과 같은 두 개(`@microsoft/agents-hosting`, `express`)만 둡니다.
일진 계산 라이브러리와 `openai` 패키지는 추가하지 않습니다. 일진은 날짜 계산 한 줄이고, LLM 호출은 `fetch` 한 번이기 때문입니다.
해시는 `node:crypto`를 씁니다. 참조 저장소의 코드와 설정은 수정하지 않습니다.

## 3. 구현 방식 비교

| 방식 | 내용 | 장점 | 단점 |
| --- | --- | --- | --- |
| **A. 발송 직전 LLM 1회 호출 (채택)** | 9:00에 등급을 계산하고 LLM을 한 번 호출해 문장을 받은 뒤 바로 발송. 실패하면 템플릿 문장 | 근황·요일 문구가 매일 새롭고 「어제」를 자연스럽게 반영 | API 키 필요, 응답 대기만큼 발송 지연 |
| B. 템플릿만 사용 | 문장 풀에서 날짜와 띠로 선택 | 외부 호출 없음 | 몇 주 안에 문장 반복, 근황이 금방 식상해짐 |
| C. 주 1회 일괄 생성 | 일요일 밤에 5일 치를 미리 생성 | 발송이 LLM 장애와 무관 | 근황의 「어제」가 실제와 어긋남, 주중 공휴일·재생성 처리 복잡 |

사용자는 A를 선택했습니다. B는 A의 실패 대비 템플릿으로 포함됩니다.

## 4. 운세 계산 규칙

### 4.1 일진

날짜는 항상 한국 시간(`Asia/Seoul`) 기준입니다.
일진 번호(0 = 갑자)는 `(율리우스 적일 + 49) mod 60`이고, 일진의 띠는 `번호 mod 12`(0 = 쥐, 1 = 소 … 11 = 돼지)입니다.
검증값: 2000-01-01 무오일, 2026-11-26 갑진일, 2026-11-27 을사일.

### 4.2 띠 관계와 별점

오늘 일진의 띠(일지)와 각 띠를 비교합니다. 여러 관계에 해당하면 위에 있는 것을 적용합니다.

| 순서 | 관계 | 짝 | 별점 |
| --- | --- | --- | --- |
| 1 | 충 | 쥐·말, 소·양, 호랑이·원숭이, 토끼·닭, 용·개, 뱀·돼지 | ★1 |
| 2 | 육합 | 쥐·소, 호랑이·돼지, 토끼·개, 용·닭, 뱀·원숭이, 말·양 | ★5 |
| 3 | 삼합 | 원숭이·쥐·용, 돼지·토끼·양, 호랑이·말·개, 뱀·닭·소 | ★4 |
| 4 | 형 | 호랑이·뱀·원숭이, 소·개·양, 쥐·토끼, 자형(용·말·닭·돼지가 같은 띠의 날을 만날 때) | ★2 |
| 4 | 해 | 쥐·양, 소·말, 호랑이·뱀, 토끼·용, 원숭이·돼지, 닭·개 | ★2 |
| 5 | 오늘의 띠 | 일지와 같은 띠(자형 제외) | ★3, 「오늘의 띠」로 표시 |
| 6 | 보통 | 나머지 | ★3 |

이 규칙으로는 매일 충 1띠(★1), 육합 1띠(★5)가 반드시 나옵니다.
펼친 내용에는 관계의 근거를 한 줄로 보여줍니다(예: 「뱀과 짝이 맞는 육합이에요…」).

### 4.3 세부 운세와 행운 항목 (구현 담당 판단으로 정한 값)

- 회의운, 점심운, 칼퇴운: `sha256(날짜 + 띠 + 항목)`에서 -2~+2를 뽑아 띠 별점에 더하고 1~5로 자릅니다. 같은 날에는 언제 봐도 같은 값입니다.
- 행운 메뉴와 행운의 색: 코드에 둔 고정 목록(메뉴 약 30개, 색 약 12개)에서 같은 해시로 고릅니다. LLM에 맡기지 않습니다.
- 금요일에는 칼퇴운에 +1을 더합니다(최대 5). 「칼퇴운부터 보세요」 문구와 맞추기 위함입니다.

### 4.4 머리글 요약

「오늘 제일 좋은 띠는 **(육합 띠)**… **(충 띠)**띠는 쉬어 가세요…」. 두 띠는 4.2 규칙으로 항상 하나씩 정해지므로 LLM이 필요 없습니다.

## 5. 문장 생성

### 5.1 LLM 호출

| 항목 | 설계값 |
| --- | --- |
| 공급자 | Gemini API의 OpenAI 호환 엔드포인트(`https://generativelanguage.googleapis.com/v1beta/openai/`) |
| 모델 | `GEMINI_MODEL`, 기본값 `gemini-3.6-flash`. 더 새로운 Flash 모델은 환경 변수로 바꿔 시험합니다 |
| 사고 수준 | `GEMINI_REASONING_EFFORT`, 기본값 `low`(구현 담당 판단). 하루 1회 호출이라 응답 속도보다 문장 품질을 우선합니다 |
| 호출 방식 | `fetch` 1회, 재시도 없음, 제한 시간 60초 |
| 응답 형식 | JSON 응답 모드. 구현 시 Gemini 문서에서 지원 방식 확인 |
| 호출 시점 | 그날 첫 발송 시점에 1회. 결과는 날짜별로 저장하고 멘션 재요청에는 저장본을 씁니다 |

### 5.2 입력과 출력

LLM에 보내는 내용: 날짜, 요일, 특별한 날 힌트, 일진, 12띠 각각의 관계와 별점, 최근 5일 근황 문장(반복 방지), 생일 쪽지 필요 여부.
**팀원 이름과 생년월일은 보내지 않습니다.** 생일 문장에는 `{이름}` 자리만 두게 하고 코드에서 채웁니다.

받는 JSON:

```json
{
  "rows": [{ "animal": "쥐", "line": "한 줄 운세", "extra": "펼친 내용의 한 줄" }],
  "news": "쓱부엉 근황 한 줄",
  "birthday": "{이름}님 … 생일 축하 문장(요청한 날만)"
}
```

검증 기준: `rows`가 쥐부터 돼지까지 순서대로 12개, `line` 40자 이하, `extra`·`news`·`birthday` 60자 이하, 빈 문자열 없음.
카드 마크다운에 영향을 주는 문자(`*`, `_`, `[`, `]`, `<`, `>`)는 제거합니다.
검증에 실패한 항목만 템플릿으로 바꾸지 않고, 응답 전체를 템플릿으로 바꿉니다. 섞여서 말투가 달라지는 것을 막기 위함입니다.

### 5.3 프롬프트 가드레일

- 말투: 짧은 존댓말, 말줄임표(…), 크게 부르지 않음. 칭찬받으면 숨는 내성적인 성격.
- 소재: 회의, 점심, 칼퇴, 메신저, 회의실 같은 회사 생활.
- 금지: 저주와 불길한 예언, 건강·투자·연애 조언, 특정인 비하.
- 충(★1)도 「쉬어 가는 날」처럼 가볍게 씁니다.
- 다른 봇(냠요정, 쿠웨이트박, 투표곰, 장부장)은 `extra`나 `news`에서 하루 1~2번만 언급합니다.
  관계 설정: 쿠웨이트박은 자꾸 판에 끌어들이려 해서 곤란함, 냠요정은 가끔 간식을 줌, 투표곰과는 말없이 같이 앉아 있는 사이, 장부장에게는 「운세는 비용 처리가 안 됩니다」라는 말을 들음.
- 특별한 날 힌트: 월요일, 금요일, 연휴 다음 날, 올해 마지막 업무일, 새해 첫 업무일(2027년 정미년, 양띠 해).

### 5.4 템플릿 대체

별점 5단계마다 `line`·`extra` 문장 10개 이상, 근황 20개 이상, 생일 문장 5개 이상을 코드에 둡니다.
선택은 같은 해시로 하므로 같은 날에는 같은 결과가 나옵니다.
운영 로그에 대체 사유(시간 초과, HTTP 오류, 형식 오류)를 남기고, 저장 시 `source`를 `template`으로 기록합니다.

## 6. 카드 구성

시안은 `docs/superpowers/specs/mockup/index.html`입니다(Adaptive Cards 3.0.6 렌더러 사용, 아이콘은 `owl.png`). 카드 버전은 1.5입니다.

1. **머리글:** 아이콘(작게, 원형), 「11월 27일 (금) 쪽지예요…」, 요일 문구(예: 「금요일이에요… 칼퇴운부터 보세요… 자기 띠를 누르면 펼쳐져요…」).
2. **생일 쪽지(해당하는 날만):** `emphasis` 상자. 「생일 쪽지」, 축하 문장, 「오늘 운세는 띠 상관없이… 전부 ★★★★★로 해 뒀어요…」.
3. **머리글 요약:** 4.4절.
4. **12줄:** 띠, 별점, 한 줄 운세, 펼침 표시(▾/▴). 줄 전체가 `Action.ToggleVisibility`로 상세 상자와 펼침 표시를 전환합니다. 별점 색은 4~5개 `Good`, 3개 `Warning`, 1~2개 `Attention`입니다.
5. **상세 상자(처음엔 숨김):** 회의운, 점심운, 칼퇴운, 행운 메뉴, 행운의 색, `extra` 한 줄, 관계 근거 한 줄.
6. **근황:** `news` 한 줄.
7. **꼬리말:** 「오늘은 을사일(뱀날)이에요… 재미로만 봐 주세요…」, 「…그럼 이만. (쓱)」.

펼침은 누른 사람의 화면에서만 일어나며 봇을 호출하지 않습니다. 카드 아이콘은 `PUBLIC_BASE_URL`의 정적 경로로 제공합니다.
실제 Teams 데스크톱과 모바일에서 펼침 동작과 카드 크기 제한(28KB)을 확인합니다.

## 7. 생일 쪽지

- 생일 목록은 환경 변수 `BIRTHDAYS`에 `이름:MM-DD` 형식으로 쉼표로 이어 적습니다(예: `홍길동:12-12,김철수:02-04`). **출생연도는 저장하지 않습니다.**
- `.env`는 Git과 ZIP에서 제외합니다. 저장소 문서와 테스트에는 실제 이름과 날짜를 쓰지 않습니다.
- 대상: 오늘이 생일인 사람과, 오늘 다음 날부터 다음 업무일 전날까지(주말·공휴일)가 생일인 사람입니다. 예: 금요일 카드에 토요일·일요일 생일을 미리 넣습니다.
- 문구 앞부분은 코드가 정합니다. 당일이면 「오늘은 ○○님 생일이에요…」, 미리 축하하면 「내일은」 또는 「주말에」 「연휴에」 다음에 「○○님 생일이 있어요… 하루 일찍 두고 가요…」를 씁니다.
- 같은 카드에 생일이 여럿이면 이름을 「○○님, ○○님」으로 이어 씁니다.
- 2월 29일 생일은 평년에 2월 28일로 봅니다.
- 나이와 띠는 표시하지 않습니다. 이름은 일반 글자이며 멘션 알림은 보내지 않습니다.

## 8. 발송과 멘션 명령

### 8.1 정기 발송

- 30초마다 실행합니다(냠요정과 같은 방식).
- 조건: 한국 시간 평일, `holidays.ts` 공휴일이 아님, 09:00~09:59, 그날 그 대화방 발송 기록 없음.
  냠요정은 정각 1분만 확인하지만, 쓱부엉은 서버 재시작으로 9시를 놓쳐도 10시 전이면 발송합니다.
- 순서: 그날 운세가 저장돼 있지 않으면 생성(LLM 또는 템플릿)해 저장 → 대화방별 발송 기록을 먼저 넣음 → 카드 발송 → 실패하면 발송 기록을 지우고 다음 주기에 재시도.
- 같은 날 LLM 호출이 겹치지 않도록 생성 중 표시를 둡니다. 생성이 끝나기 전 주기에는 발송을 건너뜁니다.

### 8.2 대화방 등록

- 냠요정과 같이 설치 또는 멘션 시 대화방 참조(ConversationReference)를 저장합니다.
- 설치 직후 한 번 인사합니다: 「저… 평일 아침 9시에 쪽지 두고 갈게요… (쓱)」.

### 8.3 멘션 명령

| 입력 | 동작 |
| --- | --- |
| `@쓱부엉`, `@쓱부엉 오늘` | 오늘 운세가 저장돼 있으면 같은 카드를 다시 보냅니다. 없으면(9시 전, 주말, 공휴일) 「오늘 쪽지는… 아직이에요… (쓱)」 |
| `@쓱부엉 도움말` | 짧은 도움말 |
| 그 밖의 입력 | 도움말과 같음 |

멘션 응답에서는 LLM을 새로 호출하지 않습니다.

### 8.4 저장 스키마

| 테이블 | 열 |
| --- | --- |
| `conversation` | `id`, `teams_conversation_id`(고유), `reference_json` |
| `daily_fortune` | `date_kst`(기본 키), `json`(카드에 필요한 계산값과 문장 전체), `source`(`llm` 또는 `template`), `created_at` |
| `delivery` | `conversation_id`, `date_kst`, `message_id`, 기본 키(`conversation_id`, `date_kst`) |

최근 5일 근황은 `daily_fortune`에서 읽습니다. 기록은 자동 삭제하지 않습니다.

## 11. 예상 비용

Gemini Developer API 가격표 기준 `gemini-3.6-flash` 유료(Standard) 단가는 100만 토큰당 입력 0.75달러, 출력 3.75달러(2026-12-31까지)이고, 2027-01-01부터 입력 1.50달러, 출력 7.50달러입니다. [1]
1회 호출 토큰 수는 아직 측정하지 않았습니다. 입력 약 2,500토큰, 출력 약 5,500토큰(사고 토큰 포함)으로 가정하면 2027년 단가로 1회 약 0.05달러, 연간 업무일 약 250일 기준 연 11달러 안팎입니다. 구현 후 실제 사용량으로 다시 계산합니다.
비교한 다른 모델의 같은 가정 기준 연간 예상: `gemini-3.5-flash-lite`(장부장 기본값) 약 3달러, Claude Sonnet 5.5 약 15달러, Claude Opus 5.5 약 30달러. 사용자는 기존 Gemini 키를 쓸 수 있는 Gemini 3.6 Flash를 선택했습니다.
무료 등급은 입력 내용이 Google 제품 개선에 쓰일 수 있으므로 어느 등급을 쓸지는 운영자가 정합니다. 이름과 생일은 LLM에 보내지 않습니다.
서버, 도메인, 봇 등록은 기존 봇과 같은 방식을 쓰므로 이 봇 때문에 새로 생기는 비용은 LLM 호출 외에는 없을 것으로 봅니다.
